支援

最後更新：2026 年 10 月 16 日

遇到問題先看下面的常見問題。需要提問時，請用應用程式內「一般 → 關於 → 回報問題」產生診斷資訊，自己看一遍之後，連同問題描述一起寄到 GitHub Issues —— 這是目前唯一的支援管道。應用程式不會自動蒐集或上傳任何內容。

常見問題

1. 為什麼我的顯示器 DDC 無回應？

因為這塊面板沒有實作 DDC/CI（顯示器控制命令集）。這不是應用程式的問題：有些顯示器、電視、擴充底座與轉接器根本不回應這類命令，我們用於測試的 UP32R7-A 就是其中之一。

此時硬體亮度、硬體音量與輸入來源切換不可用；應用程式會明確標示「DDC 無回應」，並自動把亮度交給軟體調光（透過 CoreGraphics 伽瑪表壓暗畫面）。軟體調光一樣能把螢幕調暗，但它不改變面板背光電流，所以省電幅度與硬體調光不同。

2. 捲動平滑和 Mos / Mac Mouse Fix 衝突怎麼辦？

這類工具都是透過攔截滾輪事件來做平滑的，同時開啟會互相吞掉對方的滾輪。應用程式會在啟動與執行中偵測同類工具並提示衝突。處理辦法（任選其一）：

  • 只保留一個平滑工具；
  • 在「捲動」面板裡把本應用程式的捲動平滑關掉，或反過來關掉另一個工具；
  • 保留兩者時，用「安全模式」：按住 ⌘ 捲動會臨時交回系統；看圖、簡報、地圖這類把滾輪當縮放的視窗也會自動交回系統。

3. 怎麼還原顯示器的原始狀態？

從輕到重，按順序試：

  1. 應用程式內還原：「顯示」面板底部 →「還原此顯示器」或「交回系統校正」。選單列圖示裡也能找到。
  2. 不依賴應用程式：在終端機執行 bash Scripts/restore-dimming.sh。它把亮度、色溫、預設寫回中性值，不需要應用程式正在執行。
  3. 顯示排列卡住 / 外接顯示器無法辨識：需要管理員密碼。刪除系統層級顯示設定後重新啟動：
    sudo rm /Library/Preferences/com.apple.windowserver.displays.plist
rm -f ~/Library/Preferences/ByHost/com.apple.windowserver.displays.*.plist
sudo shutdown -r now
    只刪使用者層級不夠 —— 真正存顯示排列的是系統層級那個檔案；刪完必須重新啟動。
  4. 完全進不了系統：關機 → 長按電源鍵 → 選項 → 終端機，執行 emergency-restore-display.sh（在安裝目錄的 Scripts 下）。

這些復原路徑是刻意做成不依賴應用程式的。我們曾在測試中把顯示器弄黑過，所以「能復原」是產品的硬性要求，不是附贈功能。

4. 試用結束後哪些功能還能用？

試用期（14 天）內功能完整。試用結束後只暫停 5 項增強功能：捲動平滑、滑鼠按鍵映射、護眼排程、自動化規則、工作階段儲存與回復。

復原類操作永遠可用，且不依賴連網：還原此顯示器、交回系統校正、顯示器休眠、結束、授權頁面、關於頁面、解除安裝/重置入口。換句話說，欠費不會把你鎖在一塊無法復原的螢幕前。

5. 現在可以購買/啟動嗎？

可以。購買通道已開通，使用加密貨幣收款。在下單頁選擇鏈與代幣，按頁面顯示的精確金額轉帳，鏈上確認後（通常幾分鐘）該頁會立即顯示啟動碼。你也可以把碼儲存為檔案、寄給自己，或之後用永久取碼連結 / 6 位查詢碼重新開啟。

換新 Mac：開啟「一般 → 授權」，貼上你購買時拿到的碼即可啟動——啟動是離線驗證，無需連網。同一張碼可用於你本人擁有或控制的 Mac；DP- 碼不含伺服器端強制的裝置上限，請按「一位使用者一份授權」使用。

6. 清理功能會不會刪錯東西？

設計上就是把「刪錯」的機率壓到最低：

  • 只處理 13 類有確定性重建方式的產物（Xcode DerivedData、SwiftPM、CocoaPods、npm/pnpm/Yarn、Go、Gradle、__pycache__、Rust target、當機報告、Homebrew 快取等）；
  • 永不參與清理：文件、桌面、下載項目、圖片、影片、音樂、偏好設定、Application Support、鑰匙圈、郵件、訊息、Safari；
  • 刪除前先移入隔離區，預設保留 30 天，隨時可還原；
  • 永久刪除預設不存在：全應用程式只有一個函式能永久刪除，必須同時滿足 6 個條件，任何一條不過就中止；
  • 自動化規則只能預先掃描，不能刪除。

7. 你們會自動蒐集我的資訊嗎？

不會。應用程式不做遙測、不做埋點、不上傳使用資料，也不自動上傳當機記錄。「回報問題」產生的內容只在你本機，必須由你手動複製或傳送。真正連網的只有三件事：檢查更新（預設關閉）、檢查授權（通道接通並啟用之後才有），以及你主動點擊時開啟網頁。詳見隱私政策。

怎麼回報問題

  1. 開啟「一般 → 關於 → 回報問題」，點一下產生診斷資訊；
  2. 自己看一遍內容（它會移除序號、使用者名稱、檔案路徑與授權碼，但你仍應確認）；
  3. 點「複製到剪貼板」，再到 GitHub 上新增一條 issue，把內容與問題描述一起貼進去。

附上當機記錄（如果應用程式當機過）

  1. 開啟「應用程式 → 工具程式 → 控制台」；
  2. 左側選「當機報告」（Crash Reports）；
  3. 找到 DisplayPilot 的項目，右鍵 → 在 Finder 中顯示；
  4. 把對應時間點的 .ips 檔案拖進那條 issue 作為附件。

記錄的常見位置是 ~/Library/Logs/DiagnosticReports/。

我們做不到的事

  • 不能在不支援 DDC/CI 的顯示器上提供硬體亮度/音量/輸入來源；
  • 不能保證軟體調光與硬體調光的觀感完全一致；
  • 不能替你操作 macOS 的顯示排列，復原必須按上面的步驟來；
  • 無法在鏈上撤銷加密貨幣付款。如果軟體在你這裡無法正常工作、我們又修不好，請在購買後 14 天內聯絡我們，我們會按原幣別退款（完整退款政策見授權合約）。
