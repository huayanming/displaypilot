自己驗證

LumePane 是還沒有評價的新付費應用，所以請不要信我們的話。這一頁的每條說法，都可以在你的 Mac 上用下面的命令親自核對。這裡引用的輸出，逐字來自已發布的 7.1.1 版本。

一、它真的是我們的嗎？Apple 公證過嗎？

codesign -dv --verbose=2 /Applications/LumePane.app
  Authority=Developer ID Application: yanming hua (7P2P353LBW)
  Format=app bundle with Mach-O universal (x86_64 arm64)
  flags=0x10000(runtime)

spctl -a -vv -t exec /Applications/LumePane.app
  accepted
  source=Notarized Developer ID

xcrun stapler validate /Applications/LumePane.app
  The validate action worked!

這個二進位用我們的 Developer ID 簽章，Apple 掃描並公證過，且公證憑據釘紮在應用內，因此離線也能驗證。任何被改動過的副本都過不了這三項。

二、下載的東西完整嗎？

shasum -a 256 ~/Downloads/DisplayPilot-7.1.1.dmg
  eb958a456e31ac027520ae0765ca57441d2f009c4a3a6df926c4264b5ab733de

同一個值也寫在 Homebrew cask 裡，所以你有兩個獨立的地方可以對照：

brew cat huayanming/tap/displaypilot | grep sha256
如果對不上，不要執行這個檔案。

三、它會偷偷連網嗎？

應用自己的程式碼裡只有一個網路端點：授權服務的 /api/redeem。它只在貼上短碼時被呼叫——以 DP- 開頭的長碼完全離線驗證，永不連網。自動檢查更新預設關閉（SUEnableAutomaticChecks 與 SUAllowsAutomaticUpdates 都是 false）；你若手動開啟，它只從我們站點取 appcast.xml，不取別的。

你可以自己盯：開啟應用、讓它閒置，然後在終端機執行：

lsof -i -P | grep -i displaypilot

在關閉自動更新檢查時，這條命令什麼都不輸出。應用不會向我們傳送使用資料、當機報告或任何識別碼；裡面沒有統計程式碼。

四、斷網也能啟用嗎？

關掉 Wi-Fi，把長 DP- 碼貼進授權欄，它會啟用。公鑰內嵌在應用裡：用 Ed25519 在本機驗簽，且啟用碼不綁裝置。

五、這一頁驗證不了什麼

  • 清理邏輯對不對。它只處理 13 類有確定性重建方式的產物，先隔離 30 天。我們把推理與檢查寫在審計報告裡，而不是讓你相信介面。
  • 顯示器那部分對你的面板是否合適。這正是 14 天試用存在的意義。
  • 我們好不好打交道。這沒有哪一頁能證明。寄封郵件試試。

如果上面任何一條命令的輸出與這裡寫的不一致，那是我們的文件或建置有問題——請到支援頁告訴我們，我們會公開修正。

我們怎麼審查自己的產品（以及我們錯在哪）

首頁上的那個捲動數字

首頁引用了一組實測的捲動回應改善。它來自應用程式自帶的離線基準，你可以自己跑——它用固定的時間步逐幀驅動插值器，不攔截任何真實輸入，然後把回應形狀印出來：

LumePane --scroll-selftest

在我們的測試面板（120 Hz）上，首幀從 3 點提升到 9 點，90% 用時從 150 ms 降到 133 ms。這些數字描述的是演算法的回應，不是你的硬體，所以你自己跑出來的會不一樣。
