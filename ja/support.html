サポート

最終更新：2026 年 10 月 16 日

まず下のよくある質問をご確認ください。質問が必要なときは、アプリ内の「一般 → 情報 → 問題を報告」で診断情報を生成し、ご自身で目を通したうえで、問題の説明とともに GitHub Issues へ投稿してください — 現在これが唯一のサポート窓口です。アプリが自動で何かを収集・送信することはありません。

メール: huayanming2019@gmail.com（GitHub を使いたくない場合もどうぞ）

よくある質問

1. ディスプレイが「DDC 応答なし」になるのはなぜですか？

そのパネルが DDC/CI（ディスプレイ制御コマンド セット）を実装していないためです。アプリの問題ではありません。ディスプレイ、テレビ、ドック、変換アダプターのなかには、この種のコマンドにまったく応答しないものがあり、テストに使っている UP32R7-A もその 1 つです。

この場合、ハードウェアの明るさ、ハードウェアの音量、入力ソースの切り替えは使えません。アプリは「DDC 応答なし」と明確に表示し、明るさを自動的にソフトウェア調光（CoreGraphics ガンマテーブルで画面を暗くする方式）へ引き渡します。ソフトウェア調光でも画面は暗くできますが、パネルのバックライト電流は変えないため、消費電力の削減幅はハードウェア調光とは異なります。

2. スクロール スムージングが Mos / Mac Mouse Fix と競合したら？

これらのツールはいずれもホイール イベントを横取りしてスムージングするため、同時に有効にすると互いのホイール入力を飲み込み合います。アプリは起動時と動作中に同種のツールを検出し、競合を警告します。対処は次のいずれかです。

  • スムージング ツールを 1 つだけ残す。
  • 本アプリの「スクロール」パネルでスクロール スムージングをオフにする、またはもう一方のツールをオフにする。
  • 両方を残す場合は「セーフ モード」を使う：⌘ を押しながらのスクロールは一時的にシステムへ返し、画像ビューア、スライド、地図などホイールをズームとして扱うウィンドウも自動でシステムへ返します。

3. ディスプレイを元の状態に戻すには？

軽いものから順に試してください。

  1. アプリ内で復元：「ディスプレイ」パネル下部 →「このディスプレイを復元」または「システムのキャリブレーションへ返す」。メニュー バーのアイコンからも選べます。
  2. アプリに依存しない方法：ターミナルで bash Scripts/restore-dimming.sh を実行します。明るさ、色温度、プリセットを中立値に書き戻し、アプリが起動している必要はありません。
  3. ディスプレイ配置が固まった／外付けディスプレイが認識されない：管理者パスワードが必要です。システム レベルのディスプレイ設定を削除して再起動します：
    sudo rm /Library/Preferences/com.apple.windowserver.displays.plist
rm -f ~/Library/Preferences/ByHost/com.apple.windowserver.displays.*.plist
sudo shutdown -r now
    ユーザー レベルの削除だけでは不十分です — ディスプレイ配置を実際に保存しているのはシステム レベルのファイルで、削除後は必ず再起動が必要です。
  4. システムに入れなくなった場合：電源を切る → 電源ボタンを長押し → オプション → ターミナルを開き、emergency-restore-display.sh（インストール先の Scripts 内）を実行します。

これらの復旧経路は、意図的にアプリへ依存しない形で用意しています。当方もテスト中にディスプレイを真っ黒にしたことがあるため、「必ず復旧できる」ことは製品の必須要件であり、おまけの機能ではありません。

4. トライアル終了後も使える機能は？

14 日間のトライアル中はすべての機能が使えます。トライアル終了後に一時停止するのは 5 つの拡張機能だけです — スクロール スムージング、マウス ボタンの割り当て、眼の保護スケジュール、自動化ルール、セッションの保存と復元。

復旧系の操作は常に利用でき、ネット接続も必要としません：このディスプレイを復元、システムのキャリブレーションへ返す、ディスプレイのスリープ、終了、ライセンス ページ、情報ページ、アンインストール／リセットの入口。つまり、トライアル切れで復元できない画面に閉じ込められることはありません。

5. 今すぐ購入・アクティベーションできますか？

購入できます。購入チャンネルは開通済みで、暗号資産で支払います。注文ページでチェーンとトークンを選び、表示された正確な金額を送金してください。確認後（通常数分）ライセンス コードが表示されます。コードを保存したり、後で永久リンクや 6 文字の照会用コードで再表示することもできます。

開通後の新しい Mac への移行手順は次のとおりです。新しい Mac で「一般 → ライセンス」を開き、購入メールのライセンス キーを入力してアクティベーションします。枠が満杯と表示されたら、古い Mac の同じページで「非アクティベーション」を押して枠を解放し、新しい Mac で再度アクティベーションします — 非アクティベーションはそのマシンのライセンスを外すだけで、購入には影響しません。同時にアクティベーションできる台数はライセンス サービスが決め、購入ページに記載されます。

6. クリーンアップが間違ったものを削除することはありませんか？

「間違えて削除する」可能性をできるかぎり下げる設計にしています。

  • 対象は再生成の手順が確定している 13 種類の生成物のみ（Xcode DerivedData、SwiftPM、CocoaPods、npm/pnpm/Yarn、Go、Gradle、__pycache__、Rust target、クラッシュレポート、Homebrew キャッシュなど）。
  • クリーンアップの対象に決してならないもの：書類、デスクトップ、ダウンロード、ピクチャ、ムービー、ミュージック、環境設定、Application Support、キーチェーン、メール、メッセージ、Safari。
  • 削除の前にまず隔離領域へ移動し、既定で 30 日間保持、いつでも復元できます。
  • 完全削除は既定で存在せず、アプリ全体でたった 1 つの関数だけが実行できます。6 つの条件を同時に満たす必要があり、1 つでも欠ければ中止します。
  • 自動化ルールは事前スキャンのみで、削除はできません。

7. 情報を自動で収集していませんか？

していません。アプリはテレメトリも解析も行わず、使用データやクラッシュ ログを自動でアップロードしません。「問題を報告」で生成される内容はあなたの Mac 内にとどまり、手動でコピーまたは送信しなければ出ていきません。ネットワークに接続するのは 3 つだけです — アップデートの確認（既定でオフ）、ライセンスの確認（開通してアクティベーションしたあとのみ）、そしてご自身でクリックしたときにウェブ ページを開くこと。詳細はプライバシーポリシーをご覧ください。

問題の報告方法

  1. 「一般 → 情報 → 問題を報告」を開き、クリックして診断情報を生成します。
  2. ご自身で内容を確認します（シリアル番号、ユーザー名、ファイル パス、ライセンス キーは除去されますが、それでも目を通してください）。
  3. 「クリップボードにコピー」を押し、GitHub で新しい issue を作成して、問題の説明とともに貼り付けます。

クラッシュ ログの添付（アプリがクラッシュした場合）

  1. 「アプリケーション → ユーティリティ → コンソール」を開きます。
  2. 左側で「クラッシュ レポート」を選びます。
  3. DisplayPilot の項目を見つけ、右クリック → Finder で表示。
  4. 該当時刻の .ips ファイルをその issue に添付としてドラッグします。

ログの一般的な場所は ~/Library/Logs/DiagnosticReports/ です。

できないこと

  • DDC/CI に対応していないディスプレイでは、ハードウェアの明るさ／音量／入力ソースを提供できません。
  • ソフトウェア調光とハードウェア調光の見え方が完全に一致することを保証できません。
  • macOS のディスプレイ配置を代わりに操作することはできません。復旧は上記の手順に沿って行ってください。
  • 暗号資産の支払いをオンチェーンで取り消すことはできません。本ソフトウェアが動作せず当方で解決できない場合は、購入後 14 日以内にご連絡ください。同じ通貨で返金します（詳細はライセンス）。
